# FitKeep 双端 Agent 开发计划 Implementation Plan

> **For agentic workers:** 本文是待执行的 Task 清单。开发开始前先读[协同开发交接说明](../../agent-collaboration.md)和[可行性报告](../../../agent-plugin/可行性与架构分析报告-2026-09-29.md)。按已分配的文件边界开发，交付状态只能是“待 Codex 验收”。本文不授权任何 Agent 自行部署或合并 `main`。

**Goal:** 用户和管理员分别通过 Agent 向 FitKeep Java 接口下达已登记的业务操作；管理员逐项审批数据查询和写入，社区在预授权范围内可自动隐藏明确违规内容并事后复核。

**Architecture:** Java 保有 JWT 鉴权、业务规则、数据库访问、审批执行与审计；独立的 `agent-plugin` 服务负责 DeepSeek 调用、意图规划和会话。用户端与管理员端共用运行代码，但分开入口、工具目录和上下文。现有静态页面只显示 Java 返回的结果、审批卡与固定导航目标。

**Tech Stack:** Java 21、Spring Boot 3.2、Spring Security、MyBatis、MySQL、静态 HTML/CSS/JavaScript、DeepSeek 兼容 Chat Completions。独立服务优先选择轻量 Python 3.12/FastAPI，不引入本地模型、向量库或容器 Runner；Task 00 复核 VPS 内存后冻结运行时。

## 当前基线与范围

2026-09-29 的已提交基线是 `main@0145b95`。`agent-plugin/`、`server/.../agent/`、用户端悬浮窗文件与相关配置仍是本地未提交工作；`README.md` 和 `deploy/` 还有其他本地改动。Task 00 必须先审阅、归属和固定这些草稿，不能让执行 Agent 从干净 `main` 开始却误以为已含 MVP。当前 GitHub Actions 对 `main` 的 `server/**` 变更自动发布 VPS，所有开发先在独立分支和本地环境验收。

本期“全项目操作”指当前 FitKeep **有定义的业务功能**和本计划明确补充的 Java 接口。用户端覆盖课程/视频信息、个人打卡、番茄钟记录、社区和个人资料；管理员端覆盖用户、课程、视频、社区、打卡和平台统计的可用增删改查。登录密码输入、用户未提供的文件上传、任意 SQL/HTTP、服务器命令以及纯浏览器本地计时/视频控制不由 Agent 代办。用户说“打开课程”时，Java 返回固定路由名与课程 ID，现有页面完成跳转。

### 冻结的安全契约

1. `USER` 与 `ADMIN` 两套工具目录和会话隔离；角色只从 Java 当前认证和数据库状态判断，不由模型或客户端声明。
2. 模型只能提交已登记工具名与结构化参数。Java 注入当前操作人的身份和资源归属，拒绝模型提供的 `actorUserId`、任意 URL、SQL、文件路径、Java 类名和页面选择器。管理员工具可在审批下接受类型化 `targetUserId`，它不是操作人身份。
3. 用户端只读查询与课程打开可以直接执行。用户端写入先预览并取得用户确认。管理员端涉及用户或平台数据的**每一次读取和每一次写入**都使用具体对象、字段和影响范围的审批卡。审批前不得把该次敏感查询结果传给模型。
4. 审批由 Java 持久化一次性 `actionId`、有效期、工具版本、参数摘要、管理员身份与状态。确认时重新核对角色、对象状态和参数；重复请求只能取得同一结果，拒绝跨用户或过期确认。
5. 社区自主能力仅限管理员事先启用规则后自动**隐藏明确违规内容**。不确定内容只入待审；不自动删除、封号或修改内容。每次自动隐藏留证据、可恢复并进入事后复核。监管服务身份不能调用普通管理员工具。
6. Java 是唯一业务写入者。独立 Agent 服务不直连 MySQL、不接收可复用管理员令牌；DeepSeek 密钥仅在服务端环境中保存。插件故障不影响非 Agent 业务接口。
7. 所有返回给模型的业务文本视为不可信数据，限制大小和字段；工具回执不得把未执行写成成功。真实模型、真实 Java/API、真实页面与模拟测试分别记证据。

**验收：** 能力矩阵覆盖当前控制器映射；普通用户、管理员、监管服务三种身份的调用结果明确；课程同名多匹配和未发布课程有定义行为。此 Task 仅产出契约与基线，不声称实现业务能力。Codex 技术核对后交用户亲自验收；未收到用户确认前不启动 Task 01。

### Task 01：先修现有业务接口权限

**Owner：** MiniMax Code。**文件：** `CommunityController`/`CommunityService`、`CheckInController`、`AdminController`、`FileService`、`SecurityConfig`、相关 Mapper/DTO 和 JUnit 测试。

修复普通用户可按 ID 删除非本人帖、公开帖子详情可按 ID 读取已隐藏帖、公开课程详情/视频可按 ID 读取未发布课程、`/api/checkin/all` 对普通登录者开放、管理员用户列表返回密码哈希、上传类型/大小与公开访问策略、全来源 CORS。检查 `init.sql` 的固定初始管理员口令，改为部署时由管理员安全设置，不把已知口令保留为可直接使用的默认值。保留现有合法页面功能；普通用户不能借“Agent 入口”获得新权限。若调整登录 JWT/角色有效性，提供禁用用户和降权后的回归用例。

**验收：** 先有会失败的越权测试；修复后跨用户删除、按 ID 读取隐藏帖/未发布课程、普通用户全量打卡读取、密码字段泄漏和非法上传均被拒绝，合法管理员与本人操作仍成功。新装库不出现可用的固定口令管理员账号；已部署管理员账号如何安全轮换有明确操作说明。`mvn -B -ntp -f server/pom.xml verify` 通过。

### Task 02：建立 Java Agent 网关和两套工具目录

**Owner：** MiniMax Code。**文件：** `server/src/main/java/com/server/server/agent/**`、`SecurityConfig`、对应 JUnit 测试。

从当前单体 `AgentController` 拆出认证入口、类型化工具注册、参数校验与执行器。公开端点分别以用户与管理员身份进入；只允许 Java 选择工具集合。Agent 服务请求只携带受限执行关联信息，不能携带自称的操作人身份或任意业务 URL。旧 `/api/agent/chat` 在迁移期保持用户端兼容或按 Task 00 冻结的迁移方案处理。

**验收：** USER 调用 ADMIN 工具、模型伪造 `actorUserId`、未知工具或额外字段都被拒绝；ADMIN 进入 USER 会话不会取得管理工具；插件不可用时已有课程/打卡接口照常工作。

### Task 03：审批、幂等和审计

**Owner：** MiniMax Code。**文件：** `server/.../agent/approval/**`、`ops/db/**`、`init.sql`、Mapper 与测试。生产数据库变更脚本由 Codex 独立复核后执行。

Java 创建含工具、目标、参数摘要、风险与有效期的待审批动作。管理员每次敏感查询及写入都需单独审批；用户写入也需核对内容。执行前再次验证当前角色、资源权限和对象版本；记录批准、拒绝、执行及失败；相同 `actionId` 只产生一次业务副作用。监管预授权作为独立窄权限，不复用管理员逐项审批令牌。

**验收：** 未审批查询不返回个人数据；过期、跨人、重复、改参数、降权、目标状态变化均失败关闭或返回既有结果；审计记录与真实业务变化一致。SQL 在空库及带旧数据的测试库验证，提供回滚方案。

### Task 04：独立 DeepSeek 模型服务

**Owner：** MiniMax Code。**文件：** 新建 `agent-plugin/service/**` 及其测试、服务配置说明；Java 内部通信适配器在 `server/.../agent/**`。

把模型请求、工具调用轮次和会话状态移出 Java 单体。独立服务仅监听受信地址，使用专用服务身份与 Java 通讯；不直连 MySQL，不保存用户 JWT，不暴露 DeepSeek Key 给浏览器。USER/ADMIN 对话与工具目录隔离。限制输入、上下文、工具结果、轮次、超时和并发；模型/Java 失败返回明确状态。保留无密钥环境下的可诊断启动状态，不在仓库存密钥。

**验收：** 模拟模型能触发 Java 只读工具并拿到真实 API 回执；非法服务身份、越权工具和提示注入不能执行写入；断开模型服务后主站仍可使用。真实 DeepSeek 调用单独记录模型 ID、费用与响应，不用模拟结果替代。

### Task 05：用户端查询和课程打开

**Owner：** MiniMax Code。**文件：** 用户业务服务/控制器缺口、`server/.../agent/tool/**` 与 JUnit 测试。

登记课程列表、详情、视频列表、个人打卡状态/记录、番茄钟统计/记录、可见社区帖及详情、个人资料查询。补真实 Java 课程名称搜索/定位与 `GET /api/me` 等缺口。课程打开返回已发布且可访问的固定 `COURSE_DETAIL` 路由名和 ID；多匹配时返回候选，不猜选。用户查询始终按 Java 当前身份限定。

**验收：** 给出真实课程 ID 的课程打开结果；同名、下架、不存在课程行为稳定；A 用户无法读 B 的打卡/资料；结果有字段和大小上限；模拟模型/Java 联调不虚构结果。

### Task 06：用户端 Agent 入口与导航呈现

**Owner：** ZCode。**文件：** `server/src/main/resources/static/user/agent-widget.js`、`.css`、相关用户 HTML 和前端验证文件。

把当前仅首页可用的悬浮窗接到用户主要页面；展示回答来源、工具失败、登录失效与候选课程。收到 Java 的固定导航路由名和课程 ID 后，按前端本地固定映射跳转；不接受模型给出的 URL、HTML 或选择器。课程、帖子和模型文本按纯文本渲染，不能拼入可执行 HTML。页面刷新和切换不应把上一用户的会话暴露给下一用户。

**验收：** 静态脚本语法检查通过；真实登录页面能用课程指令打开正确课程；多匹配先选择；无效/过期会话只提示重登，不误报操作成功。ZCode 提交页面证据，Codex 独立回查。

### Task 07：用户端受控写入

**Owner：** MiniMax Code。**文件：** 用户业务接口、`server/.../agent/tool/**`、审批服务和测试。

登记打卡、番茄钟记录保存、社区发帖/评论、本人帖子删除等当前业务写入。Java 做字段验证、本人归属与一次性确认；点赞需有用户级去重和频率边界。个人资料修改用 `PATCH /api/me` 明确可改字段。文件上传只能接收用户主动选择的文件，先走 Task 01 的校验。纯浏览器本地计时不在本 Task。

**验收：** 预览不写库，确认后恰好写一次；跨用户、过期、非法内容和重复点赞被拒绝；结果与 Java 业务记录一致。

### Task 08：用户写入确认界面

**Owner：** ZCode。**文件：** 用户端 Agent 静态 JS/CSS/HTML 与页面验证文件。

显示写入目标、完整内容和影响，提供确认/取消；确认按钮只提交该次 `actionId`，待处理时禁止重复触发。用户看到 Java 的最终执行结果及失败原因，不把“已提交审批”显示成“已完成业务”。文件上传先让用户亲自选择文件。

**验收：** 打卡、发帖的预览/取消/确认在真实页面正确工作；重复点击不新增记录；登录失效和服务中断可恢复。

### Task 09：管理员敏感读取与逐项审批

**Owner：** MiniMax Code。**文件：** `server/.../agent/admin/**`、审批服务、Admin/User 等必要 DTO 和测试。

登记平台统计、用户列表/详情、课程/视频管理视图、全部帖子与打卡等管理查询。每次查询先给出字段范围、过滤条件和对象规模预览；管理员确认后才执行并返回最小化 DTO。密码哈希、密钥、原始 JWT 不进模型结果。批量查询需有页大小上限，下一页是新的受控请求。

**验收：** 未审批和 USER 身份读不到管理数据；确认后只读到本次授权字段/范围；重放令牌不能扩大查询；敏感字段始终不返回。

### Task 10：管理员 Agent 查询界面

**Owner：** ZCode。**文件：** 管理端静态 HTML/JS/CSS 和页面验证文件。

增加与用户端视觉上可区分的管理入口；展示管理员查询条件与字段审批卡，确认后呈现结果和审计链接。默认不在审批前展示用户个人数据；把帖子、评论、用户昵称等不可信文本按纯文本渲染，不拼入可执行 HTML。拒绝或超时后清理待审批状态。

**验收：** 管理员真实页面完成单项查询审批；普通用户无法通过直接访问静态管理页取得管理数据；每条敏感结果可回查审批记录。

### Task 11：管理员写入工具覆盖

**Owner：** MiniMax Code。**文件：** 管理业务控制器/服务、`server/.../agent/admin/**`、审批与测试。
